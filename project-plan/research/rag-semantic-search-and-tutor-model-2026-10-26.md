# Поиск по смыслу в RAG и выбор локальной модели тьютора (2026-10-26)

Статус: **частично готово**. Поиск по смыслу включён и измерен. Настройка гибрида и сравнение моделей тьютора не закончены. Причина: 2026-10-26 в 05:53 папку `~/.ollama/models` очистили вне этой работы (вероятно, общая чистка диска). Удалены все модели: `bge-m3`, `qwen3-embedding:0.6b`, `qwen2.5-coder:7b`, `qwen3.5:latest`. Пока модели не скачаны заново, локальный тьютор не отвечает, а поиск работает только по ключевым словам.

Ветка: `feat/rag-semantic-search`, только локальные коммиты, ничего не отправлено.

## 1. Как устроен поиск

- Индекс `01_Projects/knowledge_index.py`: 80 документов из `02_Areas` и шпаргалок, 1355 фрагментов до 1200 символов. Почти все уроки двуязычные (RU + EN в одном файле).
- Поиск по ключевым словам: BM25-подобная оценка с бонусами за заголовок, название и путь, плюс совпадение по первым 5 буквам для русских окончаний.
- Поиск по смыслу: вектор вопроса сравнивается (косинус) с векторами всех фрагментов, порог 0,25.
- Гибрид: два ранжирования сливаются методом RRF (`вес / (k + место)`, сейчас k = 60, веса 1:1). В выдаче не больше 2 фрагментов на документ, всего 4 фрагмента. Тьютору уходит не больше одного фрагмента на урок.
- Без модели эмбеддингов, при ошибке Ollama или пока корпус ещё не проиндексирован, поиск работает только по ключевым словам. После ошибки повтор не раньше чем через 60 с.

## 2. Модель эмбеддингов: bge-m3

Сравнивал две многоязычные модели (скачаны с разрешения пользователя):

| | bge-m3 | qwen3-embedding:0.6b |
|---|---|---|
| Размер | 1,16 ГБ | 0,64 ГБ |
| Длина вектора | 1024 | 1024 |
| Индексация всего корпуса на M1 | 131 с | 176 с |
| Только по смыслу: hit@1 / hit@4 / MRR | 90 % / 100 % / 0,942 | 95 % / 100 % / 0,975 |
| Гибрид RRF k=60: hit@1 / hit@4 / MRR | 75 % / 90 % / 0,808 | 70 % / 95 % / 0,825 |
| Нужна инструкция перед вопросом | нет | да (`Instruct: … Query: …`, добавлена в код) |

**Рекомендация: `bge-m3` по умолчанию.** На 20 вопросах модели различаются на один вопрос, это в пределах шума. bge-m3 выбрана, потому что:

- ей не нужна инструкция перед запросом: меньше способов незаметно испортить качество;
- она на четверть быстрее индексирует корпус на M1;
- это проверенная модель для поиска с хорошими результатами на русском.

`qwen3-embedding:0.6b` — разумная замена, если важна экономия места (≈0,5 ГБ меньше). Её можно выбрать в Центре управления; инструкция для неё уже подставляется автоматически.

## 3. Сравнение поиска (20 вопросов, 10 RU + 10 EN, top-4)

Набор: `01_Projects/rag_eval_questions.json`. Вопросы перефразированы, как задал бы ученик, без копирования названий уроков. Предметы: математика, физика, биология, зоология, программирование, английский. Отдельно заранее написан контрольный набор из 10 вопросов `rag_eval_holdout_questions.json` для проверки будущей настройки; на нём ничего не подбиралось.

Запуск: `.venv/bin/python 01_Projects/rag_eval.py --embedding-model bge-m3:latest`. Все режимы идут через тот же путь выдачи, что у тьютора. Полные выдачи по каждому вопросу лежат в `rag-eval-2026-10-26/*.json`.

| Режим (bge-m3) | hit@1 | hit@4 | MRR | RU hit@4 | EN hit@4 | медиана на вопрос |
|---|---|---|---|---|---|---|
| Только ключевые слова (как сейчас без модели) | 55 % | 65 % | 0,600 | 70 % | 60 % | 0,21 с |
| Только по смыслу | 90 % | 100 % | 0,942 | 100 % | 100 % | 0,37 с |
| Гибрид RRF k=60 (код сейчас) | 75 % | 90 % | 0,808 | 90 % | 90 % | 0,40 с |

hit@1 — нужный урок на первом месте; hit@4 — среди найденных; MRR — средняя обратная позиция первого нужного урока.

Где ключевые слова ошибаются (7 из 20): «при каких x формула имеет смысл» (область определения), «скорость изменения в одной точке» (производная), «максимум при дополнительном условии» (Лагранж), «шары отскакивают без потери энергии» (упругий удар), «нервная клетка выдаёт сигнал полностью или никак», «повторить действие для каждого элемента списка», «пересказать, что спросил друг» (косвенная речь). Это вопросы без общих слов с текстом урока — именно их и решает поиск по смыслу.

**Почему гибрид хуже чистого поиска по смыслу.** С k = 60 разница между 1-м и 30-м местом мала: 1/61 против 1/90. Фрагмент, который есть в обоих списках, получает примерно двойной вес. Список по смыслу содержит почти все фрагменты (порог 0,25 для bge-m3 мягкий), поэтому любой фрагмент с одним случайным общим словом («условие», «функция», «энергия») обгоняет лучший смысловой ответ. Пример: на вопрос про Лагранжа гибрид поставил первыми уроки программирования про условия (`if`). Гибрид хуже чистого смысла на 5 вопросах и лучше только на одном («трение»).

**Что сделать дальше.** Подобрать `_RRF_K`, `_SEMANTIC_WEIGHT` и `_FUSION_CANDIDATES` в `knowledge_index.py` (у скрипта есть флаги `--rrf-k`, `--semantic-weight`, `--candidates`) и подтвердить выбор на контрольном наборе. Подбор уже был запущен, но модели удалили в процессе, и результаты непригодны. После этого скрипт оценки останавливается с ошибкой, если эмбеддинги отвалились, а не выдаёт ключевые слова за гибрид. Значения по умолчанию в коде пока не меняю: без проверки на контрольном наборе это была бы подгонка под 20 вопросов.

Оговорка: приложение ищет по запросу «предмет + название урока + вопрос». Если ученик спрашивает внутри нужного урока, поиск по ключевым словам срабатывает лучше, чем в этой оценке. Набор проверяет более трудный случай — вопрос без подсказки.

## 4. Изменения в коде

- **Фоновая индексация** (`KnowledgeIndex.warm_embeddings`, `start_embedding_warmup`). Первый проход занимает около 2 минут; Ollama вызывается вне блокировки индекса, так что вопросы в это время получают ответ по ключевым словам. Внутри запроса досчитывается не больше одного пакета из 16 фрагментов, например один короткий изменённый урок.
- **Кеш векторов в памяти** с привязкой к хешу документа. Раньше каждый вопрос заново разбирал около 27 МБ JSON из SQLite. Векторы для урока, изменённого во время прохода, отбрасываются.
- **Автоматическое включение bge-m3** (`orchestrator._sync_automatic_embedding_model`). Если ничего не выбрано явно и Ollama сообщает, что `bge-m3` установлена, модель включается при старте и при каждом `/health`. Явная модель в `OLLAMA_EMBEDDING_MODEL` или в Центре управления, включая «Отключить», важнее. Если модель удалили, поиск возвращается к ключевым словам. Выключить автоматический выбор: `OLLAMA_EMBEDDING_AUTO_MODEL=""`. `GET /settings/ollama-embedding-model` в этом случае отвечает `source: "automatic"`.
- **`/health`** отдаёт `knowledge_chunk_count`, `knowledge_embedded_chunk_count`, `knowledge_semantic_ready`. Интерфейс Swift пока их не показывает; это можно передать сессии интерфейса как прогресс индексации.

## 5. Модель тьютора: сравнение не проведено

Подготовлено, но не запущено: модели удалили раньше, чем дошла очередь.

- Скрипт: `01_Projects/tutor_model_eval.py`. Только `127.0.0.1:11434`, промпт собирается так же, как в локальном маршруте тьютора. Замеряет время до первого слова ответа, общее время, токены и `done_reason`.
- Вопросы: `01_Projects/tutor_eval_questions.json`, 10 вопросов по-русски с ожидаемыми фактами для оценки.
- Варианты: `qwen2.5-coder:7b` (сейчас по умолчанию), `qwen3.5:latest` в нынешнем виде запроса и `qwen3.5:latest,think=false`.

Что уже известно без запуска:

- `qwen3.5:latest` (9,7B, Q4_K_M, 6,6 ГБ) умеет «размышлять» (capability `thinking`). Оркестратор не передаёт `think: false` и ограничивает ответ `num_predict: 1024`. Размышление может израсходовать весь лимит; тогда стриминг вернёт пустой ответ («Ollama returned an empty streamed answer»), а первое слово появится только после размышления. Если выбирать `qwen3.5`, в запросы к Ollama скорее всего нужно добавить `think: false`. Это нужно проверить замером.
- `qwen2.5-coder:7b` (7,6B, 4,7 ГБ) — модель для кода. Для объяснений по-русски по биологии и физике это не её специализация; насколько это заметно, покажет сравнение.
- Обе модели помещаются в 16 ГБ, но не одновременно с запасом; скрипт выгружает модель после своей серии.

Рекомендацию по модели тьютора по умолчанию дам после замера.

## 7. Нужно решение пользователя

1. Скачать ли заново модели (≈12,5 ГБ): `bge-m3` 1,16 ГБ, `qwen2.5-coder:7b` 4,7 ГБ, `qwen3.5:latest` 6,6 ГБ. Без `bge-m3` нет поиска по смыслу и нельзя закончить настройку гибрида. Без моделей тьютора нельзя их сравнить, а локальный тьютор не отвечает.
