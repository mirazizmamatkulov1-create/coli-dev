## Модель эмбеддингов

- Скачаны с разрешения пользователя: `bge-m3:latest` (1,16 ГБ) и `qwen3-embedding:0.6b` (0,64 ГБ, для сравнения).
- Рекомендация на сейчас: **bge-m3**. Она многоязычная (RU/EN), не требует инструкции перед запросом, вектор 1024. По предварительным цифрам qwen3-embedding даёт сопоставимое качество; окончательное сравнение не завершено.
- Скорость на MacBook Air M1 (16 ГБ): весь корпус (80 документов, 1355 фрагментов) индексируется ≈130 с; один запрос ≈0,2 с.

## Что изменено в коде (ветка `feat/rag-semantic-search`, локальные коммиты)

- Векторы корпуса считаются в фоновом потоке. Пока первый проход не закончен, вопросы получают ответ по ключевым словам. Сразу, внутри запроса, досчитывается только небольшой пакет (до 16 фрагментов).
- Векторы кешируются в памяти с привязкой к хешу документа. Векторы для урока, который изменили во время прохода, отбрасываются.
- Если пользователь ничего не выбирал и в Ollama установлена `bge-m3`, бэкенд включает её сам. Явный выбор модели или «Отключить» в Центре управления важнее. Без модели всё работает как раньше. Отключить автоматический выбор: `OLLAMA_EMBEDDING_AUTO_MODEL=""`.
- `/health` теперь отдаёт `knowledge_chunk_count`, `knowledge_embedded_chunk_count`, `knowledge_semantic_ready` (Swift их пока не показывает).

## Сравнение поиска (20 вопросов RU/EN, top-4, `01_Projects/rag_eval.py`)

| Режим (bge-m3) | hit@1 | hit@4 | MRR | медиана на вопрос |
|---|---|---|---|---|
| Только ключевые слова | 55 % | 65 % | 0,600 | 0,21 с |
| Только смысл (векторы) | 90 % | 100 % | 0,942 | 0,37 с |
| Гибрид, текущее слияние (RRF k=60, веса 1:1) | 75 % | 90 % | 0,808 | 0,40 с |

qwen3-embedding:0.6b (старый вариант скрипта): гибрид 70 % / 95 %, только смысл 95 % / 100 %.

Вывод: смысловой поиск сильно лучше ключевых слов. Но текущее слияние RRF (k=60) почти дублирует выдачу по ключевым словам: фрагмент, совпавший хоть по одному слову, получает двойной вес. Надо подобрать параметры (`_RRF_K`, `_SEMANTIC_WEIGHT`, `_FUSION_CANDIDATES` в `knowledge_index.py`) и проверить выбор на контрольном наборе `rag_eval_holdout_questions.json`. Скрипт перебора лежит в scratchpad сессии; для этого же есть флаги `rag_eval.py --rrf-k/--semantic-weight/--candidates`.
