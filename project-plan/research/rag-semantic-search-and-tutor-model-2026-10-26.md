# Поиск по смыслу в RAG и выбор локальной модели тьютора (2026-10-26)

Ветка `feat/rag-semantic-search`, только локальные коммиты. Все замеры — на MacBook Air M1 (16 ГБ), Ollama 0.40.11, только `127.0.0.1:11434`, без облачных вызовов.

## Итог

| Вопрос | Решение |
|---|---|
| Модель эмбеддингов | **`bge-m3`** (1,16 ГБ). Включается автоматически, если установлена и ничего не выбрано явно. |
| Поиск | **Гибрид**: слова + смысл, вес смыслового списка 3:1. На 20 вопросах hit@4 вырос с 65 % до 100 %. |
| Ранжирование по словам | Больше не зависит от роста корпуса: фиксированные опорные длины плюс оценка всего урока. |
| Тьютор по умолчанию | **`qwen3.5:latest` с `think: false`** — переключено по решению пользователя. Верно по сути 10/10 против 6/10 у `qwen2.5-coder:7b`. Цена — ответ примерно вдвое дольше. |
| Лимит ответа | 1536 токенов вместо 1024; таймаут непотокового ответа 300 с вместо 90 с. |
| `think: false` | Добавлен во все запросы к Ollama. Без него `qwen3.5` давала пустой ответ на 8 из 10 вопросов. |

## 1. Как устроен поиск

- Индекс `01_Projects/knowledge_index.py`: 80 документов из `02_Areas` и шпаргалок, 1355 фрагментов до 1200 символов. Уроки двуязычные (RU + EN в одном файле).
- **По словам**: оценка по формуле BM25 с бонусами за заголовок, название и путь, плюс совпадение по первым 5 буквам для русских окончаний.
- **По смыслу**: косинусная близость вектора вопроса и векторов всех фрагментов (порог 0,25).
- **Гибрид**: два ранжирования сливаются методом RRF: `вес / (60 + место)`, вес слов 1, вес смысла 3.
- В выдаче не больше 2 фрагментов на урок и 4 фрагмента всего; тьютору уходит не больше одного фрагмента на урок.
- Без модели эмбеддингов, при ошибке Ollama или пока корпус индексируется, поиск идёт только по словам. После ошибки повторная попытка через 60 с.

## 2. Модель эмбеддингов: bge-m3

Сравнивал две многоязычные модели, обе скачаны с разрешения пользователя. Цифры ниже — до исправления ранжирования по словам, при старом слиянии 1:1; для сравнения моделей между собой это неважно.

| | bge-m3 | qwen3-embedding:0.6b |
|---|---|---|
| Размер | 1,16 ГБ | 0,64 ГБ |
| Индексация всего корпуса на M1 | 131 с | 176 с |
| Только по смыслу: hit@1 / hit@4 / MRR | 90 % / 100 % / 0,942 | 95 % / 100 % / 0,975 |
| Нужна инструкция перед вопросом | нет | да (добавлена в код) |

На 20 вопросах модели различаются на один вопрос — это в пределах шума. Выбрал **bge-m3**, потому что:
- ей не нужна инструкция перед вопросом: меньше способов незаметно ухудшить качество;
- она индексирует корпус на четверть быстрее.

`qwen3-embedding` после очистки диска 2026-10-26 заново не скачивалась.

## 3. Качество поиска (итоговая настройка, bge-m3)

Наборы:
- `01_Projects/rag_eval_questions.json` — 20 вопросов (10 RU + 10 EN), перефразированы, как спросил бы ученик, без слов из названий уроков. На нём подбирались веса.
- `01_Projects/rag_eval_holdout_questions.json` — 10 контрольных вопросов, написанных до подбора и в подборе не участвовавших.
- 16 запросов из `test_bilingual_lesson_modules_are_retrievable` — с точными терминами, формулами, `count_even`.

Запуск: `.venv/bin/python 01_Projects/rag_eval.py --embedding-model bge-m3:latest`. Все режимы идут через тот же путь выдачи, что у тьютора. Полные выдачи лежат в `rag-eval-2026-10-26/retrieval-bge-m3*.json`.

| Режим | 20 вопросов: hit@1 / hit@4 / MRR | 10 контрольных: hit@1 / hit@4 / MRR | 16 запросов с терминами: hit@1 |
|---|---|---|---|
| По словам, старое ранжирование (`origin/main`) | 55 % / 65 % / 0,600 | — | 100 % |
| По словам, новое ранжирование | 55 % / 75 % / 0,650 | 80 % / 100 % / 0,900 | 100 % |
| Только по смыслу | 90 % / 100 % / 0,942 | 90 % / 90 % / 0,900 | 100 % |
| Гибрид 1:1 (было) | 75 % / 95 % / 0,842 | 100 % / 100 % / 1,000 | 100 % |
| **Гибрид 3:1 (стало)** | **90 % / 100 % / 0,942** | **100 % / 100 % / 1,000** | **100 %** |

hit@1 — нужный урок первым; hit@4 — среди найденных; MRR — средняя обратная позиция первого нужного урока. Медиана времени поиска: по словам 0,09 с, гибрид 0,19 с на вопрос.

- **Почему гибрид 1:1 был хуже чистого смысла.** С k = 60 разница между 1-м и 30-м местом мала (1/61 против 1/90), а фрагмент, попавший в оба списка, получает примерно двойной вес. Поэтому фрагмент с одним случайным общим словом («условие», «функция», «энергия») обгонял лучший смысловой ответ. Пример: на вопрос про Лагранжа первыми выходили уроки программирования про `if`.
- **Почему не чистый смысл.** На контрольном наборе только смысл пропустил вопрос про `If I were you` (90 %), а гибрид его нашёл.
- **Подбор.** Перебирал k ∈ {10, 20, 60}, вес смысла ∈ {1, 2, 3} и ограничение кандидатов ∈ {нет, 20}. При весе 3 результат не зависит от k и ограничения (MRR 0,942–0,950). Взял минимальное изменение — только вес.
- **Остались два промаха на первом месте**, нужный урок при этом всё равно в выдаче: «при каких x формула имеет смысл» (первым выходит «Функции как модели») и вопрос про Лагранжа (первым «Условия и циклы»).
- Оговорка: приложение ищет по запросу «предмет + название урока + вопрос». Внутри нужного урока поиск срабатывает лучше, чем в этой оценке, которая проверяет вопрос без подсказки.

## 4. Устойчивость ранжирования по словам (задача от сессии математики)

- **Симптом.** В ветке `content/math-accuracy-pass` уроки математики стали длиннее, и тест `test_bilingual_lesson_modules_are_retrievable` начал падать на запросе «результат количество длительность … present perfect»: первым выходил `English/lessons/intro.md`.
- **Причина.** Нормализация длины в BM25 шла от средней длины фрагмента по всему корпусу. Рост уроков в одном предмете сдвигал близкие места в другом; на `main` запас был около 1 %.
- **Исправление** (коммит `e806ec9`):
  1. длина нормируется по фиксированным опорным значениям: 64 токена для фрагмента, 1024 для урока (близко к средним на октябрь 2026);
  2. оценка фрагмента складывается с оценкой всего урока, обе делятся на лучший результат по вопросу, поэтому урок по теме вопроса обгоняет абзац с повторёнными словами.
- **Проверка.**
  - Новый тест `test_lesson_ranking_is_stable_when_the_corpus_grows`: к копии `02_Areas` добавлены 30 длинных нейтральных уроков, а уроки математики удлинены. Первое место сохраняется для всех 16 запросов. На старом коде тест падает именно на этом запросе.
  - Копия корпуса из ветки математики: `test_knowledge_index.py` и `test_math_lesson_quality.py` проходят все (106).
  - Запас по худшему запросу около 4 % и не уменьшается при +300 и +1000 синтетических фрагментов; у старого кода он был от +1 % до −4 %.
  - Все 16 запросов проходят при любой опорной длине от 40 до 120 токенов.
- Тексты уроков и сам тест не менялись. Список запросов вынесен в константу `_BILINGUAL_MODULE_QUERIES`, содержимое то же.

## 5. Модель тьютора

**Как проверял.** 10 вопросов по-русски из `01_Projects/tutor_eval_questions.json`: математика, физика, биология, программирование. Промпт собран так же, как в локальном маршруте тьютора (системный промпт, рубрика предмета, фрагменты RAG в JSON). Скрипт — `01_Projects/tutor_model_eval.py`. Ответы целиком лежат в `rag-eval-2026-10-26/tutor-answers.md`, сырые данные — в `tutor-answers.json`.

Модели:
- `qwen2.5-coder:7b` — 7,6B, GGUF Q4_K_M, 4,7 ГБ;
- `qwen3.5:latest` — 9,7B, MLX `nvfp4`, 7,6 ГБ. После повторной загрузки это другая сборка, чем была до очистки диска (раньше GGUF на 6,6 ГБ).

### Скорость и надёжность

| | qwen2.5-coder:7b | qwen3.5, запрос как в приложении до правки | qwen3.5, `think: false` |
|---|---|---|---|
| Пустые ответы | 0 / 10 | **8 / 10** | 0 / 10 |
| Обрезано лимитом 1024 токена | 0 / 10 | 10 / 10 | 3 / 10 |
| Медиана времени ответа | **67 с** | 163 с | 144 с |
| Медиана до первого слова | **16 с** | — | 29 с |
| Скорость генерации | 9–11 ток/с | 5–10 ток/с | 6–10 ток/с |
| Загрузка модели | 3,9 с | 5,5 с | 5,0 с |

Промпт занимал 1350–2430 токенов. Без `think: false` модель `qwen3.5` тратит все 1024 токена ответа на скрытые рассуждения, и приложение получает пустой ответ («Ollama returned an empty streamed answer»). Поэтому `think: false` теперь передаётся во все запросы оркестратора к Ollama (`_ask_ollama`, `_stream_ollama`). Модели без этого режима флаг игнорируют — проверено на `qwen2.5-coder:7b`.

### Точность и понятность (ручная оценка по ожидаемым фактам)

| Вопрос | qwen2.5-coder:7b | qwen3.5, `think: false` |
|---|---|---|
| Область определения 1/(x − 2) | верно | верно |
| Производная x² в точке 3 | верно | верно; лишнее вступление про «недоверенные данные» |
| Горизонтальный бросок (2 с, 20 м) | верно | верно; обрезан в самом конце, языковые сбои («抛出», «проектiles») |
| Теплота Q = cmΔT (84 кДж) | верно | верно; правильно сослался на 4186 Дж/(кг·°C) из урока |
| Трение покоя и скольжения | **неверно**: «F = ma обратно пропорциональна ускорению», нет μs > μk | верно, с числовым примером |
| Эритроцит в дистиллированной воде | частично: вывод верный, выдумки про генотип и «эрозию почв» | верно (гипотонический раствор, лизис); путаное вступление о сроке перепроверки урока, «плазма» внутри клетки |
| Решётка Пеннета Aa × Aa | верно; мелкая ошибка «генотип — в гамете» | верно, наглядная решётка |
| Потенциал действия «всё или ничего» | частично: нет Na⁺-каналов и положительной обратной связи | верно: порог, Na⁺, обратная связь, частотный код |
| Слишком большой шаг обучения | частично: расходимость названа «переобучением», путаный пример | верно по сути; ошибка в примере кода, путаный абзац «сопутствующие проблемы» |
| Транзакция при переводе денег | верно; выдуманный пункт ACID «неповторимость» | верно, с примером из урока (80/20, перевод 30) |
| **Верно / частично / неверно** | **6 / 3 / 1** | **10 / 0 / 0** |

**Понятность по-русски.** У обеих моделей ответы по шагам. У `qwen2.5-coder` язык суше и местами неуклюжий («Принцип Ньютона о втором движении», «сила статики»), а в биологии — откровенные выдумки. У `qwen3.5` объяснения подробнее, с аналогиями и проверками. Недостатки `qwen3.5`: иногда пересказывает служебные правила промпта о сроках перепроверки источников, редкие вставки чужих символов, ответы длиннее (1,7–3,9 тыс. знаков против 0,7–2,1 тыс.).

### Рекомендация и что сделано

По умолчанию теперь **`qwen3.5:latest` с `think: false`** (`DEFAULT_OLLAMA_TUTOR_MODEL`; переопределяется `OLLAMA_RESEARCHER`). `qwen2.5-coder:7b` остаётся запасной быстрой моделью: её можно выбрать для предмета в Центре управления или задать через `OLLAMA_RESEARCHER`. Для учебного приложения главное — достоверность: у `qwen2.5-coder` из 10 ответов один неверный и три с ошибками, у `qwen3.5` ошибок по сути нет.

Цена перехода:
- ответ примерно вдвое дольше (медиана 2,4 мин, первое слово около 30 с на M1);
- модель на 3 ГБ больше (7,6 ГБ; вместе с bge-m3 помещается в 16 ГБ).

Сделано вместе с переключением:
1. `num_predict` поднят с 1024 до 1536 (`OLLAMA_NUM_PREDICT`). Живая проверка через настоящий маршрут `stream_local` на двух вопросах, которые раньше обрывались (трение, потенциал действия): оба ответа завершены, около 4,7 тыс. знаков; первое слово через 19–28 с, весь ответ через 2,7–2,9 мин.
2. Таймаут непотокового ответа поднят с 90 до 300 с (`OLLAMA_ANSWER_TIMEOUT_SECONDS`). Такой ответ приходит только целиком, а 1536 токенов при ~8 ток/с занимают до ~3,5 мин вместе с промптом. Для потокового ответа 90 с — ожидание между кусками, его не менял.
3. `.env.example`: `OLLAMA_RESEARCHER=qwen3.5:latest`.

Осталось на потом: подправить блок промпта о сроках перепроверки источников — `qwen3.5` иногда пересказывает его ученику. На машине без `qwen3.5:latest` локальный маршрут будет «не готов», пока модель не установят или не выберут другую.

## 6. Изменения в коде

- **Фоновая индексация** (`KnowledgeIndex.warm_embeddings`, `start_embedding_warmup`). Первый проход занимает около 2 минут; Ollama вызывается вне блокировки индекса, поэтому вопросы в это время получают ответ по словам. Внутри вопроса досчитывается не больше одного пакета из 16 фрагментов.
- **Кеш векторов в памяти** с привязкой к хешу документа: каждый вопрос больше не разбирает около 27 МБ JSON из SQLite. Векторы урока, изменённого во время прохода, отбрасываются.
- **Автовключение bge-m3** (`orchestrator._sync_automatic_embedding_model`). Если ничего не выбрано явно и Ollama сообщает, что модель установлена, она включается при старте и при каждом `/health`. Явная модель в `OLLAMA_EMBEDDING_MODEL` или в Центре управления, включая «Отключить», важнее. Если модель удалили, поиск возвращается к словам. Выключить автоматический выбор: `OLLAMA_EMBEDDING_AUTO_MODEL=""`.
- **`/health`** отдаёт `knowledge_chunk_count`, `knowledge_embedded_chunk_count`, `knowledge_semantic_ready`. Интерфейс их пока не показывает; это можно сделать прогрессом индексации в Центре управления.
- **Устойчивое ранжирование по словам** и **вес смысла 3:1** — см. разделы 3 и 4.
- **`think: false`** в запросах к Ollama — см. раздел 5.
- **Скрипты оценки** останавливаются с ошибкой, если эмбеддинги отвалились посреди прогона: так результаты по словам не выдаются за гибрид. Это случилось однажды, когда модели исчезли с диска во время подбора.
